# ORM 热路径性能优化

本次优化保留文档根锁、单实例缓存、脏字段代次、增量操作符、版本过滤、写入确认和丢失确认后的重试。优化集中在调度唤醒、原生值处理和快照复制。

## 实测结果

2026-11-23，Windows 11 / Python 3.13.15 / MongoDB 8.0.4，独立的本机回环服务，`w=1`，默认 journaling。基线为提交 `975e865`，优化版为本次工作区。两个版本使用同一套测量脚本、同一服务，交替运行各 5 轮；以下为中位数。原始样本保存在 [优化前](../performance-before.json) 和 [优化后](../performance-after.json)。

| 测量项 | 优化前 | 优化后 | 前后耗时比 |
| --- | ---: | ---: | ---: |
| 100,000 次缓存命中 | 185.23 ms | 137.34 ms | 1.35× |
| 100,000 次单线程属性赋值 | 263.53 ms | 155.22 ms | 1.70× |
| 100,000 次属性赋值，8 个业务线程 | 5,584.55 ms | 167.61 ms | 33.32× |
| 列表写入包生成，100,000 个整数 | 70.07 ms | 19.79 ms | 3.54× |
| 字典写入包生成，10,000 个键 | 19.45 ms | 9.88 ms | 1.97× |
| 集合写入包生成，10,000 个整数 | 31.43 ms | 19.47 ms | 1.61× |
| 列表首次加载 | 65.31 ms | 23.41 ms | 2.79× |
| 列表增量落库，含写入包生成和确认 | 98.22 ms | 37.02 ms | 2.65× |
| 字典增量落库，含写入包生成和确认 | 24.73 ms | 11.88 ms | 2.08× |
| 集合增量落库，含写入包生成和确认 | 34.65 ms | 21.79 ms | 1.59× |
| 1,000 个标量文档排空 | 381.89 ms | 343.18 ms | 1.11× |

列表生成写入包的临时 Python 分配峰值从 4,869,294 B 降到 3,780,278 B，减少约 22%；集合从 2,796,893 B 降到 2,101,154 B，减少约 25%。这是单次 capture 的 tracemalloc 峰值，测量开始前已有的缓存和快照不计入其中，不代表整个进程的内存用量。

并发赋值的优化前样本为 4.85–5.83 秒，优化后为 0.16–0.51 秒，线程调度影响明显。33.32× 是本负载的中位耗时之比，不能推广为生产数据库吞吐提升。其他项目也受硬件、网络、文档大小和写确认设置影响。

缓存负载包含 1,000 个文档，每个文档赋值 100 次；8 个业务线程各自处理不同的文档。首次排空使用 8 个数据库线程，待执行队列容量为 32。并发赋值再执行一次相同的赋值序列，最终值与已确认值一致，随后确认未产生额外文档写入。

容器负载每轮重新加载一个文档。列表追加 2 个整数，字典修改一个值，集合新增一个整数。每轮对同一脏状态生成 5 次写入包，确认增量操作符后排空一次，直接读取 MongoDB 检查最终内容。写入包计时排除网络；落库计时包含写入包生成、调度和数据库确认。初次加载与内存测量分别计量。

## 修改及稳定性验证

- 重复赋值保留首次 flush 截止时间，减少无用通知；新文档、失败解除和调度参数变化仍会唤醒调度线程。在途写入结束时处理更新的代次，队列满时等待可用容量。
- 原生不可变标量走精确类型分支，原生 list/dict 使用保留别名和循环关系的复制。Enum、BSON 驱动类型和自定义子类继续使用原来的转换或 deepcopy 语义。
- 调用 PyMongo 的原始 BSON 编码函数，避免仅为比较字节而创建 BSON 子类对象。数组比较继续区分 `1`、`True` 和 `1.0`。
- 捕获时先分离数据，再构造操作符；每次数据库尝试复制操作符。成功确认后将已退役写入包的数据移交给快照，避免再次复制完整字段。可变 BSON 叶值也不能随后续缓存赋值改变在途写入。

真实 MongoDB 上 117 项测试全部通过，其中包含 7 项真实服务器测试。新增的并发压力测试使用 16 个业务线程、16 个文档、512 次业务调用、8 个数据库线程和容量为 2 的队列，注入写入成功后丢失确认。直接读取数据库验证计数、嵌套字典、列表、集合、版本号和未知字段，确认没有重复追加、丢失更新或缓存身份变化。

新增回归检查还覆盖持续修改不推迟首次 flush、已有待写文档在调度参数变化后自动写入、容量为 1 的队列排空、在途更新、可变 BSON 叶值隔离、驱动类型及自定义转换。Ruff 格式和静态检查、Pyright 均通过。wheel 构建成功，核对了源码、Python 版本元数据和 `py.typed`，并通过独立 wheel 导入及模型检查。

## 复现

准备独立的 MongoDB 服务，从项目根目录执行：

```powershell
$env:MONGODB_URI = 'mongodb://127.0.0.1:27017'
.\.venv\Scripts\python.exe examples\benchmark_hot_paths.py --rounds 5 --output performance-current.json

$env:PYORM_TEST_URI = $env:MONGODB_URI
.\.venv\Scripts\python.exe -m pytest -q
```

脚本只清理自己创建的随机 `pyorm_benchmark_hot_paths_*` 数据库。比较版本时让同一脚本分别导入基线与优化后的包，固定所有负载参数并交替运行；输出的 `implementation_path` 可以确认实际加载的包。
